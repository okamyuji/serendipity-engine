# Embedding システム仕様書

## 概要

ノートのコンテンツをベクトル化し、セマンティック検索とAI発見機能の基盤を提供します。OpenAI の text-embedding-3-small モデルを使用して、1536次元のベクトル表現を生成します。

## 機能要件

### FR-EMB-001: 自動Embedding生成

ノートが作成または更新されたとき、自動的にEmbeddingを生成します。

入力として、ノートIDを受け取ります。

処理の流れは以下の通りです。

1. ノートのコンテンツをChunkingServiceで分割します
2. 各チャンクに対してEmbeddingを生成します
3. 生成したEmbeddingをデータベースに保存します
4. ConnectionBuildJobをキューに追加します

出力として、成功時はチャンクレコードの配列を返し、失敗時はエラーを記録します。

### FR-EMB-002: チャンク分割

長いコンテンツを適切なサイズのチャンクに分割します。

入力として、ノートのコンテンツテキストを受け取ります。

処理の詳細は以下の通りです。

- 最大チャンクサイズは2000文字です
- チャンク間のオーバーラップは200文字です
- 段落単位で分割を優先します
- 段落が長すぎる場合は文単位で分割します

出力として、チャンク情報の配列を返します。各要素にはコンテンツと位置情報が含まれます。

### FR-EMB-003: Embedding生成

テキストからベクトル表現を生成します。

入力として、テキスト文字列を受け取ります。

処理の詳細は以下の通りです。

- OpenAI API の text-embedding-3-small モデルを使用します
- テキストを正規化します（空白の統一、前後のトリム）
- 8000文字を超える場合は切り詰めます

出力として、1536次元のfloat配列を返します。

### FR-EMB-004: 一括Embedding生成

複数のテキストを効率的にEmbedding化します。

入力として、テキスト配列を受け取ります。

処理の詳細は以下の通りです。

- OpenAI APIのバッチ処理機能を使用します
- 各テキストを正規化します
- APIコール回数を削減します

出力として、Embeddingベクトルの配列を返します。

## データモデル

### chunks テーブル

各カラムの詳細は以下の通りです。

- id: bigint型、主キー
- note_id: bigint型、NOT NULL制約、外部キー（notesテーブルを参照）
- content: text型、NOT NULL制約、チャンクのテキスト内容
- embedding: vector型（1536次元）、Embeddingベクトル
- position: integer型、DEFAULT 0、チャンク内での位置
- created_at: datetime型、NOT NULL制約、作成日時
- updated_at: datetime型、NOT NULL制約、更新日時

インデックスの設定は以下の通りです。

- note_id に通常のインデックス
- embedding に HNSW インデックス（vector_cosine_ops）

HNSW インデックスにより、高速な近似最近傍検索が可能になります。

## バックグラウンドジョブ

### EmbeddingJob

ノート保存時に自動的にキューに追加されます。

実行内容は以下の通りです。

1. ノートを取得します
2. EmbeddingServiceを使用してEmbeddingを生成します
3. 既存のチャンクを削除します
4. 新しいチャンクを保存します
5. ConnectionBuildJobをキューに追加します

キュー名は default で、リトライ設定は以下の通りです。

- OpenAI::Error の場合、最大3回リトライします
- 待機時間は多項式的に増加します

### ConnectionBuildJob

Embedding生成後に自動的にキューに追加されます。

実行内容は以下の通りです。

1. ノートを取得します
2. ConnectionAnalyzerを使用してコネクションを構築します
3. 類似度の高いノートとのコネクションを作成します

キュー名は low です。

## エラーハンドリング

### EmbeddingError

Embedding生成に失敗した場合に発生します。

発生条件は以下の通りです。

- OpenAI API キーが未設定の場合
- OpenAI API からエラーレスポンスが返された場合
- ネットワークエラーが発生した場合

対処方法は以下の通りです。

- ジョブのリトライ機構により自動的に再試行されます
- 最大リトライ回数を超えた場合はログに記録されます

## パフォーマンス考慮事項

### Embedding生成の最適化

以下の最適化を実施しています。

- バッチ処理により API コール回数を削減します
- チャンクサイズを調整してトークン数を最適化します
- 非同期ジョブにより UI のブロッキングを回避します

### ベクトル検索の最適化

以下の最適化を実施しています。

- HNSW インデックスにより検索速度を向上させます
- コサイン距離を使用して類似度を計算します
- ユーザーごとにスコープを限定して検索範囲を絞ります

## セキュリティ

### API キーの管理

OpenAI API キーは環境変数で管理します。

- OPENAI_API_KEY 環境変数に設定します
- 本番環境では Rails credentials で暗号化します
- ログやエラーメッセージに API キーを含めません

### データの保護

Embeddingデータは個人情報を含む可能性があります。

- ユーザーごとにアクセス制御を実施します
- 削除されたノートのチャンクは CASCADE により自動削除されます
- バックアップ時も適切に暗号化します
