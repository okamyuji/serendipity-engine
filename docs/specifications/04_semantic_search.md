# セマンティック検索仕様書

## 概要

ベクトル類似度に基づくセマンティック検索機能を提供します。キーワードの完全一致ではなく、意味的な類似性に基づいてノートを検索できます。

## 機能要件

### FR-SEARCH-001: キーワード検索

従来の全文検索機能を提供します。

入力として、以下のパラメータを受け取ります。

- q: 検索クエリ文字列（必須）
- limit: 結果の最大件数（任意、デフォルト10件）

処理の詳細は以下の通りです。

- タイトルと本文に対して ILIKE 検索を実行します
- 大文字小文字を区別しません
- 部分一致で検索します

出力として、マッチしたノートの配列を返します。

### FR-SEARCH-002: セマンティック検索

意味的な類似性に基づく検索機能を提供します。

入力として、以下のパラメータを受け取ります。

- q: 検索クエリ文字列（必須）
- limit: 結果の最大件数（任意、デフォルト10件）

処理の流れは以下の通りです。

1. クエリ文字列の Embedding を生成します
2. ユーザーのチャンクから類似度の高いものを検索します
3. チャンクが属するノートを取得します
4. 重複を除去します
5. 類似度スコアを付与します
6. 類似度でソートします

出力として、類似度スコア付きのノート配列を返します。

### FR-SEARCH-003: ハイブリッド検索

キーワード検索とセマンティック検索を組み合わせます。

入力として、以下のパラメータを受け取ります。

- q: 検索クエリ文字列（必須）
- mode: 検索モード（keyword / semantic / hybrid）
- limit: 結果の最大件数（任意、デフォルト10件）

処理の詳細は以下の通りです。

- hybrid モードでは両方の検索を実行します
- 結果をマージして重複を除去します
- スコアを正規化して統合します

出力として、統合されたノート配列を返します。

### FR-SEARCH-004: フィルタリング

検索結果をさらに絞り込みます。

入力として、以下のパラメータを受け取ります。

- project_id: プロジェクトでフィルタ（任意）
- tag_ids: タグでフィルタ（任意）
- date_from: 作成日の開始日（任意）
- date_to: 作成日の終了日（任意）

処理の詳細は以下の通りです。

- 検索結果に対して追加のフィルタを適用します
- 複数のフィルタを AND 条件で組み合わせます

出力として、フィルタリングされたノート配列を返します。

## データモデル

### 検索結果の構造

各検索結果には以下の情報が含まれます。

- note: ノートオブジェクト（id, title, content, project, tags を含む）
- similarity_score: 類似度スコア（0.0〜1.0）
- search_type: 検索タイプ（keyword / semantic）
- matched_chunk: マッチしたチャンクの内容（セマンティック検索の場合）

## アルゴリズム

### コサイン類似度の計算

ベクトル間の類似度をコサイン類似度で計算します。

計算式は以下の通りです。

```text
similarity = dot_product(A, B) / (magnitude(A) * magnitude(B))
```

値の範囲は -1.0 から 1.0 です。

1.0 に近いほど類似度が高くなります。

### HNSW インデックスによる近似最近傍探索

高速な検索のために HNSW（Hierarchical Navigable Small World）インデックスを使用します。

特徴は以下の通りです。

- O(log n) の検索時間複雑度を実現します
- 高次元ベクトルに対して効率的に動作します
- 近似解を返すため、完全な精度は保証されません

パラメータ設定は以下の通りです。

- 距離メトリック: コサイン距離
- インデックスタイプ: HNSW
- オペレータクラス: vector_cosine_ops

### スコアの正規化

異なる検索手法のスコアを統一します。

正規化の方法は以下の通りです。

- キーワード検索: マッチ数を最大マッチ数で除算します
- セマンティック検索: コサイン類似度をそのまま使用します（0.0〜1.0）
- ハイブリッド: 両スコアの加重平均を計算します

## API エンドポイント

### GET /api/v1/search

キーワード検索を実行します。

クエリパラメータは以下の通りです。

- q: 検索クエリ
- limit: 結果件数

レスポンス形式は以下の通りです。

```json
{
  "results": [...],
  "query": "検索クエリ",
  "search_type": "keyword"
}
```

### GET /api/v1/search/semantic

セマンティック検索を実行します。

クエリパラメータは以下の通りです。

- q: 検索クエリ
- limit: 結果件数

レスポンス形式は以下の通りです。

```json
{
  "results": [
    {
      "id": 1,
      "title": "...",
      "content": "...",
      "similarity_score": 0.85,
      "project": {...},
      "tags": [...]
    }
  ],
  "query": "検索クエリ",
  "search_type": "semantic"
}
```

## パフォーマンス考慮事項

### 検索速度の最適化

以下の最適化を実施しています。

- HNSW インデックスにより検索を高速化します
- ユーザーごとにスコープを限定します
- 結果件数を制限します（デフォルト10件）
- プロジェクトやタグでの事前フィルタリングを推奨します

### キャッシュ戦略

以下のキャッシュを実装しています。

- 頻繁な検索クエリの結果をキャッシュします
- キャッシュの有効期限は5分です
- ノートの更新時にキャッシュを無効化します

## エラーハンドリング

### 検索エラー

以下のエラーケースに対応します。

- クエリが空の場合: 空の結果配列を返します
- Embedding 生成に失敗した場合: HTTP 503 を返します
- データベースエラーの場合: HTTP 500 を返します

エラーレスポンスの形式は以下の通りです。

```json
{
  "error": "エラーメッセージ"
}
```

### タイムアウト

長時間かかる検索を防ぎます。

- 検索のタイムアウトは30秒です
- タイムアウト時は部分的な結果を返します
- ログにタイムアウトを記録します

## セキュリティ

### アクセス制御

以下のアクセス制御を実施します。

- 認証済みユーザーのみが検索できます
- ユーザーは自身のノートのみを検索できます
- 他のユーザーのノートは検索結果に含まれません

### クエリのサニタイゼーション

以下のサニタイゼーションを実施します。

- SQL インジェクション対策を実施します
- 特殊文字をエスケープします
- クエリ長を制限します（最大1000文字）
