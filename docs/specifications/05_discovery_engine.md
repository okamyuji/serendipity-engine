# AI発見エンジン仕様書

## 概要

ユーザーのナレッジベースから意外なつながりや忘れられた知識を発見し、セレンディピティ体験を提供します。複数の発見アルゴリズムを組み合わせて、ユーザーに価値ある洞察を届けます。

## 機能要件

### FR-DISC-001: 忘れられた宝石の発見

長期間アクセスされていない価値あるノートを再浮上させます。

入力として、ユーザーIDを受け取ります。

処理の流れは以下の通りです。

1. 30日以上アクセスされていないノートを抽出します
2. アクセス回数が3回以上のノートに限定します
3. 最近のノートとの類似度を計算します
4. 類似度の高いペアを発見として生成します

出力として、forgotten_gem タイプの発見配列を返します。

条件の詳細は以下の通りです。

- last_accessed_at が 30日前より古い
- access_count が 3回以上
- 最近30日以内に更新されたノートとの類似度が 0.75 以上

### FR-DISC-002: クロスドメインブリッジの発見

異なるプロジェクト間の予期しないつながりを発見します。

入力として、ユーザーIDを受け取ります。

処理の流れは以下の通りです。

1. ユーザーのプロジェクトを取得します（2つ以上必要）
2. プロジェクト間の全組み合わせを生成します
3. 各組み合わせで最も類似度の高いノートペアを探します
4. 類似度が閾値を超えるペアを発見として生成します

出力として、bridge タイプの発見配列を返します（最大3件）。

条件の詳細は以下の通りです。

- 異なるプロジェクトに属するノート同士
- 類似度が 0.75 以上
- 両方のノートにチャンクが存在する

### FR-DISC-003: 最近の関連性発見

最近更新されたノートと予期しない関連を発見します。

入力として、ユーザーIDを受け取ります。

処理の流れは以下の通りです。

1. 7日以内に更新されたノートを取得します
2. 各ノートに対して異なるプロジェクトのノートを検索します
3. 類似度の高いノートを発見として生成します

出力として、daily タイプの発見配列を返します（最大3件）。

条件の詳細は以下の通りです。

- updated_at が 7日以内
- 異なるプロジェクトに属するノート
- 類似度が 0.75 以上

### FR-DISC-004: 日次発見の自動生成

毎日自動的に全ユーザーの発見を生成します。

入力として、全ユーザーを対象とします。

処理の流れは以下の通りです。

1. ノートが5件以上のユーザーを対象とします
2. 各ユーザーに対して発見を生成します
3. 1日あたり最大5件の発見を生成します
4. エラーが発生しても他のユーザーの処理を継続します

出力として、生成された発見の総数を返します。

実行タイミングは毎日午前6時です。

### FR-DISC-005: 発見の閲覧

ユーザーが自身の発見を閲覧できます。

入力として、認証済みユーザーを受け取ります。

処理の詳細は以下の通りです。

- 未閲覧の発見のみを取得します
- 有効期限内の発見のみを取得します
- 関連性スコアの降順でソートします
- 最大10件を返します

出力として、発見の配列を返します。

### FR-DISC-006: 発見へのアクション

ユーザーが発見に対してアクションを実行できます。

入力として、発見IDとアクションタイプを受け取ります。

アクションの種類は以下の通りです。

- act: 発見を承認してコネクションを確定します
- dismiss: 発見を却下します
- view: 発見を閲覧済みにします

処理の詳細は以下の通りです。

- act の場合、source_note と target_note 間にコネクションを作成します
- dismiss の場合、dismissed フラグを true にします
- view の場合、viewed フラグを true にします

出力として、更新された発見オブジェクトを返します。

## データモデル

### discoveries テーブル

各カラムの詳細は以下の通りです。

- id: bigint型、主キー
- user_id: bigint型、NOT NULL制約、外部キー（usersテーブルを参照）
- discovery_type: string型、NOT NULL制約、発見のタイプ（bridge / forgotten_gem / daily / learning_path）
- source_note_id: bigint型、外部キー（notesテーブルを参照）、発見の起点ノート
- target_note_id: bigint型、外部キー（notesテーブルを参照）、発見の対象ノート
- explanation: text型、発見の説明文
- relevance_score: float型、関連性スコア（0.0〜1.0）
- viewed: boolean型、DEFAULT false、閲覧済みフラグ
- acted_upon: boolean型、DEFAULT false、アクション実行済みフラグ
- dismissed: boolean型、DEFAULT false、却下フラグ
- expires_at: datetime型、有効期限
- created_at: datetime型、NOT NULL制約、作成日時
- updated_at: datetime型、NOT NULL制約、更新日時

インデックスの設定は以下の通りです。

- user_id, discovery_type, viewed の複合インデックス
- user_id, created_at の複合インデックス

## アルゴリズム

### 類似度計算

ノート間の類似度をコサイン類似度で計算します。

計算方法は以下の通りです。

1. 各ノートの最初のチャンクの Embedding を取得します
2. コサイン類似度を計算します
3. 0.0〜1.0 の範囲で正規化します

閾値の設定は以下の通りです。

- SIMILARITY_THRESHOLD = 0.75
- この値以上の類似度を持つペアのみを発見として生成します

### 発見の優先順位付け

複数の発見候補から優先度の高いものを選択します。

優先順位の基準は以下の通りです。

1. 関連性スコアが高い
2. 発見タイプが bridge（異なるドメイン間のつながり）
3. 忘れられた期間が長い（forgotten_gem の場合）
4. 最近更新された（daily の場合）

最大生成数は1日あたり5件です。

### 説明文の生成

発見に対する説明文を生成します。

現在の実装は以下の通りです。

- テンプレートベースの説明文を使用します
- ノートのタイトルとプロジェクト名を含めます

将来の拡張として、LLM を使用した動的な説明文生成を検討します。

## バックグラウンドジョブ

### DailyDiscoveryJob

毎日午前6時に実行されます。

実行内容は以下の通りです。

1. 全ユーザーを取得します
2. ノートが5件未満のユーザーはスキップします
3. 各ユーザーに対して DiscoveryEngine を実行します
4. エラーが発生してもログに記録して継続します

キュー名は low です。

## API エンドポイント

### GET /api/v1/discoveries

発見の一覧を取得します。

レスポンス形式は以下の通りです。

```json
[
  {
    "id": 1,
    "discovery_type": "bridge",
    "source_note": {
      "id": 10,
      "title": "ノートA"
    },
    "target_note": {
      "id": 20,
      "title": "ノートB"
    },
    "explanation": "「プロジェクトA」と「プロジェクトB」に予想外のつながりが見つかりました",
    "relevance_score": 0.85,
    "viewed": false,
    "acted_upon": false,
    "dismissed": false,
    "expires_at": "2024-01-15T00:00:00Z",
    "created_at": "2024-01-08T06:00:00Z"
  }
]
```

### GET /api/v1/discoveries/:id

特定の発見の詳細を取得します。

閲覧時に viewed フラグが自動的に true になります。

### POST /api/v1/discoveries/:id/act

発見を承認してコネクションを確定します。

処理の詳細は以下の通りです。

- acted_upon フラグを true にします
- source_note と target_note 間にコネクションを作成します
- コネクションの confirmed フラグを true にします

### DELETE /api/v1/discoveries/:id/dismiss

発見を却下します。

処理の詳細は以下の通りです。

- dismissed フラグを true にします
- 以降の一覧には表示されません

### POST /api/v1/discoveries/generate

手動で発見を生成します。

処理の詳細は以下の通りです。

- 現在のユーザーに対して発見を生成します
- 日次制限（5件）を超えない範囲で生成します

## パフォーマンス考慮事項

### 発見生成の最適化

以下の最適化を実施しています。

- バックグラウンドジョブで非同期実行します
- ユーザーごとに独立して処理します
- エラーが発生しても他のユーザーに影響しません
- チャンクの検索にインデックスを活用します

### 日次制限

以下の制限を設けています。

- 1日あたり最大5件の発見を生成します
- 既に5件生成済みの場合はスキップします
- 日付が変わるとカウンターがリセットされます

## セキュリティ

### アクセス制御

以下のアクセス制御を実施します。

- ユーザーは自身の発見のみを閲覧できます
- 他のユーザーの発見にはアクセスできません
- 発見の source_note と target_note は同じユーザーに属します

### データの整合性

以下の整合性を保証します。

- 削除されたノートを参照する発見は自動的に削除されます（CASCADE）
- 有効期限切れの発見は一覧に表示されません
- 却下された発見は一覧に表示されません

## テスト要件

### 単体テスト

以下の項目をテストします。

- 各発見タイプの生成ロジック
- 類似度計算
- 優先順位付け
- 日次制限の動作

### 統合テスト

以下の項目をテストします。

- エンドツーエンドの発見生成フロー
- バックグラウンドジョブの実行
- アクションの実行とコネクション作成

### パフォーマンステスト

以下の項目をテストします。

- 大量のユーザーに対する発見生成
- 大量のノートからの発見抽出
- メモリ使用量
